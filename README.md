# japanese-study

매일(평일) GitHub Actions가 일본어 학습 자료(PDF)를 자동 생성해 이메일로
발송하는 개인용 자동화 스크립트입니다.

## 무엇을 하는가

1. 그날의 레벨(JPT 300~900 또는 JLPT N4~N0, 경어 카테고리 포함)을 결정
2. 주제를 정함 — N2 이상은 NHK RSS 뉴스 제목, N3/N4·경어는 고정 주제풀
3. Gemini API로 해당 레벨 어휘·문법에 맞는 읽기 자료(20문장, 또는 A/B
   대립 의견문 각 10문장)를 생성
4. 문장 완성도·분량·경어 상투구 과다 여부를 검증, 실패 시 재시도
5. PDF로 만들어 이메일 발송, 실행 로그는 별도 알림 메일로 발송

## 핵심 설계 원칙 (왜 이렇게 만들었는가)

- **레벨 순환은 결정적(deterministic)이어야 한다.** 상태 파일 없이 날짜만으로
  그날의 레벨을 재현 가능하게 계산한다(주간 셔플백 시드 = 그 주 월요일 날짜,
  JLPT 7일 순환 = 고정 epoch부터의 경과일 계산). 이렇게 해야 실행 중간에
  기록이 유실되어도 스케줄이 깨지지 않는다. 상태를 저장하는 파일/DB가
  전혀 없는 순수 함수이므로, 수동 실행(workflow_dispatch)으로 임의 레벨을
  강제 지정해도 다음 스케줄 실행의 레벨 계산에는 아무 영향을 주지 않는다
  (다음 실행도 항상 같은 날짜 → 같은 레벨로 재현됨).
- **RSS는 제목·URL만 가져오고 본문은 가져오지 않는다.** NHK RSS에서 얻는
  것은 기사 제목과 링크뿐이며, 이 제목을 주제 삼아 Gemini가 학습 자료를
  처음부터 새로 창작한다(기사 본문 크롤링·요약이 아님). 따라서 별도의
  저작권 처리 로직(출처 표시 문구, 인용 범위 제한 등)을 두지 않았다 —
  원문을 재게시·요약하는 것이 아니라 제목만 착안점으로 쓰기 때문이다.
  PDF에는 참고용으로 주제와 원문 링크를 표기한다.
- **경어(敬語)는 오직 (경어) 카테고리에서만 발동한다.** 확률적으로 섞이면
  검증도 프롬프트 설계도 복잡해지므로, 경어 발동 경로를 하나로 고정했다.
- **경어 문서는 사내향/사외향을 분리한다(우치소토 원칙).** 자사 상사·동료를
  사외 인물과 동일하게 존경어로 다루는 것은 실제 일본어 화법상 오류이기
  때문에, 문서 종류에 따라 존경어/겸양어 지시를 다르게 준다.
- **프롬프트 고정화를 피하기 위해 매번 시드를 랜덤 조합한다.** 장르×관점,
  장소×사건 등을 곱셈으로 조합해 주제 풀을 키우고, 학습 포커스(N1 문법·
  관용표현)도 Gemini가 매번 능동 선정하게 해 상투구 반복을 줄인다.
- **N1/N0 문법·관용표현은 이력을 남겨 반복을 피한다.** 위 "상태 없는 순수
  함수" 원칙의 유일한 예외 — 학습 항목만큼은 실행 간 이력이 없으면 같은
  단어가 계속 반복돼 새 어휘를 못 배우는 문제가 생기므로, 최근 채택 항목을
  `study_history.json`에 커밋해 최근 20회 윈도우로 회피 지시한다
  (`STUDY_HISTORY_WINDOW`). 레벨 순환 자체는 여전히 상태 없이 계산된다.
- **생성 실패는 조용히 넘어가지 않는다.** 문장 검증에 실패하면 온도를
  낮춰가며 재시도하고(온도 사다리), 그래도 실패하면 워크플로우 자체를
  실패 처리해 알림 메일로 확인할 수 있게 한다.
- **Gemini 모델은 폴백 체인으로 유지한다.** 특정 세대 모델이 서비스
  종료되거나 일시적으로 과부하/한도 초과 상태여도 다음 모델로 자동 전환한다.

## 파일 구성

- `get_japanese.py` — 전체 로직(레벨 선택, 주제 선택, Gemini 호출, 검증,
  PDF 생성, 이메일 발송)이 담긴 단일 스크립트
- `.github/workflows/japanese_study.yml` — 평일 스케줄 실행 + 수동 실행
  (레벨 강제 지정 가능) GitHub Actions 워크플로우
- `study_history.json` — N1/N0 문법·관용표현 최근 채택 이력(반복 회피용).
  워크플로우가 실행마다 갱신해 커밋한다
- `MANUAL.md` — 운영 중 문제 발생 시 대응 절차, 작업 지시서 작성 원칙

## 설정 방법

### 필요한 GitHub Secrets

| Secret | 용도 |
|---|---|
| `GMAIL_ADDRESS` | 발신 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | Gmail 앱 비밀번호 |
| `GEMINI_API_KEY` | Gemini API 키 |
| `EMAIL_RECIPIENTS` | 스케줄 실행 시 추가 수신자(쉼표/공백 구분, 선택) |
| `MANUAL_MAIL_TO` | 수동 실행 시 학습 자료 메일의 유일한 수신자 |
| `NOTIFY_EMAIL` | 성공/실패 결과 알림 메일(로그 첨부)의 수신자 |

### 로컬 실행

```
pip install requests beautifulsoup4 fpdf2 python-dotenv lxml google-genai
```

`.env` 파일에 위 Secrets와 동일한 키를 넣으면 로컬에서도 `python
get_japanese.py`로 실행 가능. 일본어 폰트가 필요하며, 자동 탐색에 실패하면
`JAPANESE_FONT_PATH` 환경변수로 `.ttf` 경로를 직접 지정한다.

### 수동 실행 (workflow_dispatch)

Actions 탭에서 레벨을 지정해 실행하면 그날의 자동 로직을 무시하고 지정
레벨로 생성한다. 결과물은 `MANUAL_MAIL_TO` secret 주소로만 발송된다(테스트
격리 목적).
